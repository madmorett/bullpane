Changelog

Last updated 8 September 2026

Every version of Bullpane and what it changed for you. Docker images are published per version: ghcr.io/madmorett/bullpane:0.1.0, :0.1, :latest.

0.1.0

8 September 2026

The free edition no longer has a login. Start the container, open it, use it — no account, no first-run wizard, no SESSION_SECRET. Authentication is what Pro adds.

Changed

  • No login on the free edition. Every screen is open, so an evaluator meets the product before they meet a form. The dashboard says what that means: a “No login” badge where the account menu would be, and a warning at boot when an open instance is reachable from outside the host.
  • Pro turns the login on. Activating a key brings back accounts, roles and sessions on the next request, with no restart, and asks you to create the first admin. A lapsed licence reopens the dashboard the same way.
  • Audit rows written while open carry the IP and anonymous — the honest answer for a dashboard anyone could have reached. Nothing is lost: the history is already there when you upgrade.
  • Pro is now USD 39/month or USD 390/year, still one installation with unlimited users.

0.0.1

8 September 2026

First tagged version. The releases before it were development milestones and were not published; this is the baseline.

Added

  • Per-group settings in the BullMQ Pro groups view. Each group shows its status in Pro's own vocabulary — waiting, limited, maxed, paused — plus jobs waiting and how many are prioritized, active jobs against the group's concurrency cap, its rate limit, and when a rate-limited group returns to rotation.
  • Group jobs in the order Pro serves them: the group's list first, then its prioritized jobs.
  • Single sign-on (Pro). OIDC and SAML, with an environment-level password escape hatch so a misconfigured identity provider cannot lock you out of your own installation.
  • Payload sizes in job lists. A payload too large to preview shows its size and links to the job instead of an empty cell.
  • Discovery progress. On a Redis with millions of keys the queue list takes a few scan passes; the overview says so instead of letting a partial list pass for the whole truth.

Changed

  • Queue discovery finds queues with a live worker immediately and covers any keyspace over successive passes instead of giving up on large ones. Deleted queues disappear on the next pass.
  • Large payloads no longer set the cost of a page or a search. Sizes are checked before the data is read, and a search stops after a fixed budget and hands back a cursor. On 1 MB payloads a page of 200 jobs went from 290 ms of Redis time to 7 ms, and a search from 12.5 s to 8 ms.
  • The queue setup panel reports groups as counts per status and how many carry a per-group override.

Fixed

  • BullMQ Pro queues could show no groups at all. Verified against @taskforcesh/bullmq-pro 7.48 with real workers: a queue whose groups were all at their concurrency cap looked empty.
  • Group settings keys appeared as phantom queues in the sidebar and in queue search.
  • Waiting counts for a Pro group ignored prioritized jobs.

The dashboard itself

Also part of 0.0.1: everything the open-source dashboards do, behind a real login, plus the Pro features.

Added

  • Queues and jobs. Every BullMQ state, per-minute completed and failed rates from BullMQ's own metrics counters, and an attention view for the queues that need you.
  • Job pages with data as a tree or raw JSON, options, return value, stack traces, logs, progress and parent/child links.
  • Actions. Add, retry, promote, remove and discard jobs, in bulk if you like; pause, resume, clean, retry-all, drain and obliterate queues, with the destructive ones behind the admin role.
  • Search inside job data, bounded and resumable so a big state never blocks Redis.
  • Job schedulers listed with their pattern, run count and next run.
  • Redis health monitor. Memory, CPU, commands per second, latency, clients and keys, sampled on the server and shared across tabs.
  • Command palette (⌘ K) over every queue on every connection.
  • Pro. Alerts to Slack or any webhook, users and roles, folders, the flow graph, and an append-only audit log with CSV export.
  • Read-only mode that refuses every write, for pointing the dashboard at production before you trust it.
